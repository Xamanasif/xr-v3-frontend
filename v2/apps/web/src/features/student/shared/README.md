# `features/student/shared/` — what more than one Student screen group reads

Settled for the Student V3 migration (ST-ANALYSIS §5; groups: **home** ST-01–04, ST-19 · **hub**
ST-05 header/tabs/Overview, ST-06–ST-10 · **progress** ST-15–ST-18 · **assess** ST-11–ST-14 and the
ST-05 Assessment tab). A file here either is shared (owned by the shared-pieces agent, API frozen)
or is owned by one group (named below) with a frozen API where another group imports it. A group
that needs a change to a frozen API asks the shared-pieces agent / the lead; it never edits a file
it does not own.

Outside this folder, one more file is imported across a boundary:
`st-18-my-device/device-entry.ts` (**progress**) — `useMyDeviceEntry()` is read by the workspace
frame (`features/shared/workspace-frame/workspace-frame.tsx`, the lead's) to offer "My device" in
the account menu; its name and answer stay. `st-11-assessments/assessment-rows.ts` is read by the
hub's Assessment tab — both are the assess group's, so it is not shared.

Page components imported by `src/app/student/**` (the lead's routes) keep their names and props:
`StudentHome`, `MyCourses`, `MyCourse`, `ExperimentHub`, `HubAssessmentTab`, `Resources`,
`SimulationChooser`, `WebSimulation`, `FormatPage`, `ExperimentProgress`, `StudentAssessments`,
`AssessmentIntro`, `AssessmentAttempt`, `AssessmentResult`, `Progress`, `FormatFeedback`,
`MyDevice`.

The V3 kit pieces more than one group draws are `packages/ui/src/v3/st.tsx` (`St…` names); their
words are `src/copy/st-shared.ts`. The full settlement (copy entries, link targets, tests and
specs per group) is recorded in the migration's `ST-SETTLED.md`.
