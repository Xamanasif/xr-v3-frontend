## Executive summary

- **The B2B spine exists and is well engineered:** public catalogue → selection basket → request form → status page → Super Admin decision (internal/external) → payment step → activation → access plan → Institute Admin → Faculty/Students. It runs on a typed domain with a separate state machine for requests, institutions and plans, with about 250 unit tests in 15 B2B test files and about 50 B2B e2e tests (not run in this audit).
- **Commerce does not exist.** No price, quote, amount, currency, tax, receipt, invoice, transaction history, bundle or simulated gateway screen exists, in code or in any frozen design. This is deliberate: ND-08, ND-12 and T-05 are open; ADR-0007 TE-4 authorises a provider-neutral, **amount-free** stand-in; "no price on a public page" (17/05:228).
- **"Payment" today is an instant stand-in confirmation, and only in a local `development` build.** Any other build (staging/production, so any normal hosted build) leaves payments "Payment not confirmed" for ever and also loses browser persistence, Reset and the other stand-ins.
- **Known B2B defects and dead ends** are already reproduced and documented in `v2/docs/v3/phase2/P1-DECISION-REGISTER.md`, none implemented:
  - a duplicate institution on a repeat request
  - renewal/more licences change no plan, and IA-17 says "Access active"
  - "Information requested" has no exit; no decline
  - licences are not counted
  - group-timing view mismatch
- **A hosted demo with independent browser data is architecturally easy** (the world already lives per browser; the TE-6 snapshot exists). It is **blocked by owner authorisations**: the stand-ins are "local prototype build only"; TE-8 says "the permissive sample sign-in is never deployed publicly"; there is a "no scenario selector" rule. It is also blocked by **data**: 7 institutions, not 12, and the prepared worlds live outside the repo.
- **New commerce screens have no design authority.** No PU V3 export exists, the decline/record-payment/create screens are registered as excluded, and the design pack says "Do NOT invent or migrate unsupplied role designs". Design (or an authorised interim) must come before build.

### 2.2 Missing steps for a realistic B2B commerce demo, by journey order

1. **Requester identity** after submission: re-entry from another device, a contact e-mail outbox (simulated), and conversion into the first IA account.
2. **Quote**: what the approved scope costs (experiments × formats × licences × term, currency, taxes), shown after approval and before payment.
3. **Simulated payment step**: a clearly labelled simulated gateway with explicit outcomes (success · failure · pending) and a payment reference. Today confirmation is implicit and instant.
4. **Receipt** on success, failure notice on failure, and a payment history per request (requester/IA) and across institutions (SA).
5. **SA payment operations**: resolve pending, mark offline or purchase-order payment, close an unpaid approval.
6. **Decision completeness**: decline/close, resume after information, match to an existing institution.
7. **Post-activation commerce**: renewal and more licences that actually change the plan; adding experiments; licence usage "n of N".
8. **Onboarding**: IA invitation or activation (simulated), IA replacement.

## 7. A hosted prototype with independent browser data

### 7.1 What already works in our favour

- **There is no server state at all.** The world lives in each browser (`platform/runtime.ts`: "Nothing exists on the server"). Every visitor's browser therefore has its **own independent world** by construction. With TE-6, that world survives reloads and is shared by that browser's tabs, which keeps cross-role hand-offs in one browser working: SA approves → IA assigns → Student learns.
- **The snapshot is safe to keep in a browser.** It is versioned and checksummed, holds no password, session or receipt, and withholds request tokens. A corrupt or foreign save is rejected and a clean world starts (`persistence/snapshot.ts:1-22`).
- **The hosted origin is isolated.** `localStorage` is per origin. A hosted URL never shares data with the Mac `localhost:3360/3361` demo, so that demo is untouched.
