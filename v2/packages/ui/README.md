# @xr/ui

The frozen v46 visual system of the XR Learning Platform (`design/handoff-v46/`, decision record
`docs/decisions/ADR-0001-css-architecture-and-tailwind.md`): the eight v46 stylesheets copied byte
for byte into one cascade layer, a small documented product layer, and React components that emit
the v46 class names and ARIA exactly. No third-party design system.

Phase 0 status (WP-0.7): the stylesheets, the generated constants and icon registry, and the 42
Phase-0 components (foundation, forms, data display, overlays, shell primitives — `LEDGER.md`) are
exported from `@xr/ui`, with DataTable's sort and the B1-10 fix (WP-0.7). Links are injected through
`LinkProvider` (no `next/*` here). `src/testing/` is test support only and is never built or
exported. Role navigation and shell composition are WP-0.8; public and sign-in pieces are Phase 1
(G-8).

## Styles — `@xr/ui/styles.css`

```
src/styles/
  index.css        the only entry: @layer properties, theme, xr.v46, xr.product, utilities; then the imports
  v46/xr-*.css     the 8 v46 stylesheets, byte-identical to design/handoff-v46 (never edit)
  v46/art/*.svg    the 19 SVGs they reference with url("art/…"), byte-identical
  product.css      the xr.product layer: PF-01 … PF-13 deltas, each citing its id and evidence
```

- **One `xr.v46` layer for all eight sheets**, imported in the B8-07 order (foundation, public,
  workspace, learning, assess, vendor, govern, admin). Between the unlayered board sheets
  specificity decides first; per-sheet layers would invert that (Appendix E §2.2).
- **Never edit `src/styles/v46/`.** `v46-provenance.test.ts` checks the 27 files against
  `design/handoff-v46/SHA256SUMS.txt` (with a one-byte mutation check), the uncached repository
  scan of `pnpm verify` checks them again, and `.prettierignore` keeps `pnpm format` away. Every
  production delta goes into `product.css`.
- **`product.css` only adds rules.** Each rule names its PF id and evidence (Appendix E §2.3).
  Product-only class names use `xr-x-*`, product-only custom properties `--xr-x-*` (T-4).
- **No Tailwind inside `@xr/ui`** (`xr/v46-class-names`). The web app's composition utilities live
  in `apps/web/src/app/globals.css`, in the `utilities` layer.
- **Public Sans** is loaded by each app's root layout with the boards' own Google Fonts link (VD-02
  fallback; START-HERE Known exception 7). Self-hosted files wait for gate G-5c.

## Icon registry

`src/icons/registry.ts` is generated by `scripts/generate-icon-registry.mjs`
(`pnpm --filter @xr/ui generate:icons`) from the frozen boards: the 48 icons named on board 02, the
32 other paths the boards draw statically and 1 drawn only by board scripts ("Expand menu"), each
named from its use, plus the 4 format glyphs. `src/icons/registry.test.ts` fails when the committed
file and the boards disagree. The generator sits next to the constants generator in
`packages/ui/scripts/` rather than the `v2/tools/` the plan sketches, so its drift test can import it.

## Constants

`src/tokens/v46-constants.ts` is generated by `scripts/generate-v46-constants.mjs` from
`handoff/tokens.json` and the sheet copies: the approved container-query thresholds (600, 760, 860,
1024, 1280) and the two focus colours. Every other value stays a CSS custom property in
`xr-foundation.css :root` — there is no second token system. `v46-constants.test.ts` fails when the
committed file, `tokens.json` or the stylesheet `:root` drift apart.

## Spike record — the CSS pipeline (WP-0.5, 12 Oct 2026)

Appendix F WP-0.5 and ADR-0001 required a spike through the real build: Next.js 16.3.4
(Turbopack) with `@tailwindcss/postcss` 4.3.3. It was run on a temporary route that was deleted
afterwards; the lasting checks are `apps/web/e2e/styles.spec.ts` and the specimen harness suites.

| Question                                                         | Result                                                                                                                                                                                                                                                                                             |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Does `@import … layer()` survive the pipeline?                   | Yes. The built chunk holds `@layer xr.v46{…}` with the eight sheets in B8-07 order, then `@layer xr.product{…}`. The minifier rewrites the layer statement (for example to `@layer theme;` … `@layer utilities;` around the blocks), but every chunk still meets the layers in the declared order. |
| Do `url("art/…")` references resolve from the workspace package? | Yes. All 19 SVGs are emitted under `/_next/static/media/`, served as `image/svg+xml`, byte-identical to the handoff.                                                                                                                                                                               |
| Is the order independent of which chunk loads first?             | Yes, because every CSS entry starts with the layer statement. Checked in fresh documents with the layout chunk and a route chunk in both orders, with the imports in `layout.tsx` reversed, and against a negative control (a chunk without the statement loading first does break the order).     |
| Single-layer cascade                                             | `.xr-btn.xr-btn--text.xg-del[aria-disabled="true"]` computes `#5C6389`, not the delete red.                                                                                                                                                                                                        |
| Preflight                                                        | None in the built CSS (checked against a fingerprint of `tailwindcss/preflight.css`).                                                                                                                                                                                                              |

The concatenation fallback was not needed. Two browser facts shaped the tests: Chromium fixes the
layer order when it first meets a layer, so reordering `<link>` elements in a loaded page proves
nothing (each permutation is a fresh document); and `.xr-btn` transitions its colour, so computed
colours are read after running transitions settle.

## WP-0.5 engineering adjustments — accepted by the owner (12 Oct 2026)

The owner accepted these four implementation mechanisms for the prototype in the WP-0.6
authorisation (12 Oct 2026). Each follows the approved intent but not its literal wording, is
evidenced in the code and is checked by a test. Broader provisional decisions are not resolved by
this acceptance: VD-08 (the dialog alignment mapping), VD-23 and the rest stay PROVISIONAL.

- **Layer statement:** `@layer properties, theme, xr.v46, xr.product, utilities;` — the approved
  four in the approved order, preceded by `properties`, the layer Tailwind 4 creates for its
  `@property` fallback once a utility such as `shadow-e1` is used. Declared first it is the
  weakest layer; undeclared, the bundle meets it last and it would override the utilities in
  browsers without `@property` (`apps/web/src/app/globals.test.ts` compiles `shadow-e1` to prove
  the order). ADR-0001 §3 lists the four layers only.
- **PF-05 public menu scrim:** fixed to the viewport below the header (its top inset is the
  header height), not with `inset: 0`. The scrim sits inside the header's stacking context, so
  `inset: 0` would dim the header and cover its Close button, which B1-01 "Mobile 375 · menu
  open" draws undimmed.
- **PF-11 focus under the focused-task bar:** root `scroll-padding-top` as the register says, but
  only while focus is inside the task page (`:root:has(… .xr-page :focus:not(.xa-q, .xr-dialog *))`:
  question cards keep v46's own scroll-margin and dialog contents scroll inside the dialog), at
  113 px. Measured in Chromium 153: unscoped, it scrolls the page by about 460 px when focus
  enters the bar itself; `scroll-margin-top` on the controls does not stop focus landing under
  the bar. Accepted subject to the long-title and wrapped-bar verification in WP-0.8.
- **PF-04 dialog alignment (VD-08):** modifier classes `xr-x-dialog--start`, `--end`, `--decision`
  (top from 908 px of app width, bottom below — the AR-4 rule of the canvas `xg-dlg`) and `--marks`
  (top from 1024, bottom below — FA-19, the canvas `xw-dlg-top xa-dlg-auto`); centred without a
  modifier; a bottom sheet below 600 px whatever the modifier. The four classes are the only
  product classes besides the PF-01 sort classes (`PRODUCT_CLASS_ALLOW_LIST`,
  `@xr/config/policy-terms`). Enforced three ways: `xr/v46-class-names` (className attributes),
  `xr/product-class-allow-list` (every string in @xr/ui source) and the rendered-class component
  tests (`expectStylesheetClassesOnly`).

Open for later work packages: the public root's viewport min-height (PF-02, VD-23) shows a white
band under short pages such as B1-09 sign-in; a focused-task bar wrapped by a long title can be
taller than PF-11's 113 px (an exact value needs the FocusedTaskShell, WP-0.8).

## WP-0.7 — DataTable sort and the B1-10 fix: owner decisions (13 Oct 2026)

The PF-01 sort control follows Appendix E §7.1 (VD-04: CONFIRMED defect, PROVISIONAL design). The
owner accepted WP-0.7 functionally on 13 Oct 2026, approved the header-look correction below and
acknowledged the engineering choices listed here. None of the items below changes another
component or screen.

- **One sort state, two controls.** `DataTable` takes a controlled `sort` (column key, direction,
  `onSortChange`; the caller sorts the rows). The sorted column's `th[aria-sort]` holds
  `button.xr-x-th-sort` + `span.xr-x-th-text`; `DataTableSortBar` (the same `sort` object) goes in
  the ListToolbar's `sortBar` slot as `div.xr-x-table-sortbar`. The product layer displays the
  header button from 760 px of content and the sort bar below it, at exactly the width where v46
  clips the header; the other is `display:none` (no Tab stop, not in the accessibility tree).
- **Placement (VD-04) — accepted as an accessibility correction; remains a documented v46 visual
  deviation.** Below 760 px of content the sort bar sits in the `xr-toolbar-status` row, after the
  count and before the filter chips, above the first row ("Received, newest first" + chevron, a
  small text button: 36 px tall, so the row grows from 32 to 36 px). No board draws it; the B1-10
  frames "Filtered · Under review", "Mobile 375" and "Mobile 375 · More filters open" carry it as
  an expected deviation (Appendix E §9.1).
- **Header button look — corrected (PF-01 visual correction, owner-approved 13 Oct 2026).**
  `product.css` gives `.xr-table th .xr-x-th-sort` exactly the declarations every B1-10 table
  draws inline on its sort button (min-height 32 px, padding 0, colour #40476B, weight 700, no
  underline, 14 px), in the product layer rather than inline (Appendix E §2.5). "Received" reads as
  the grey header words beside it and the head row is 56.5 px, as drawn (it was a blue underlined
  text button in a 64.5 px row). Measured equal to B1-10's own head, injected beside the DataTable
  in the harness (`apps/specimens/e2e/datatable-sort.spec.ts`); hover keeps the colour as the
  board's inline style does; the focus ring, names, `aria-sort`, sorting and the 759/760 swap are
  unchanged. The sort bar keeps its §7.1 look; no other table or header control is affected.
- **Acknowledged by the owner:** the names by `aria-label` (both buttons exactly "Received, newest
  first. Change order" / "Received, oldest first. Change order"; the §7.1 `span.xr-sr` suffix
  gives "Received , newest first…" in Chromium because v46 `.xr-sr` is absolutely positioned);
  the status announcement (a change of order is announced in the table's mounted `role=status`
  region in the sort bar's words, once the reordered rows show; the first order is not; leaving
  the table clears the words); sort-in-place ownership (the caller reorders the rows it holds in
  the same render; if a caller does load for an order, focus on the header button moves to the
  table, as after "Try again"); and the sort bar shown only while the table lists rows.
- **Kept as they were:** the WP-0.5 hidden-header guards for `.xr-table`, `.xp-ftable` and
  `.xp-compare` (tested for every control kind they name); FailedState and the other WP-0.6 open
  items (the five inline-style gaps in `LEDGER.md`, Stepper, ErrorSummary, format chips).
- **Deferred:** the SA-02 route test (`apps/web/e2e/a11y/datatable-sort.spec.ts`, `fixme` until
  SA-02 exists in Phase 1); R-15 explicit table roles in labelled-row mode wait for a VoiceOver
  check (Chromium keeps the table semantics; WebKit is not run, P0-28).
