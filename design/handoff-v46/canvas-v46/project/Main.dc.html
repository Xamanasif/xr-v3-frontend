How to read this canvas

Fourteen boards in three rows. Read left to right. Boards 01–04 define the system, 05–08 apply it to the global families, 09–13 prove it holds across archetypes, dialogs, widths and assistive technology.

Row 1 · System

Colour, surfaces, spacing, type, components, status words, format chips and the shared state grammar.

Row 2 · Shell + global families

The one workspace shell for all seven roles, their sidebars, the account menu, Help & support and system / message pages.

Row 3 · Patterns + proof

Ten page archetypes, three dialogs, responsive frames at real widths, accessibility and motion notes, and the change log from B2.

Rules every board follows

  • One main question per screen. Overviews show attention, one status line, at most two next actions — no KPI walls.
  • Full-width reading sections, stacked. A side panel only for one focused task, at about 70–80 / 20–30. Never 50 / 50 dense columns.
  • Status in words. Colour and icon support meaning; they never carry it alone.
  • One primary action per screen. Return, send back, withdraw, pause and decline-type actions ask for a reason.
  • BITS Pilani / WILP identity is an approved asset. The lockup file was not in the design package, so every board shows the labelled placeholder — never a redrawn mark.
  • Public Sans is the working typeface, kept from B2 and swappable through one token. It is not the official WILP font.
  • No fabricated immersive evidence. No 3D models, runtime screenshots or device claims.
  • No demo or developer controls in any stakeholder-facing surface. State switches live in the canvas Tweaks panel only.
