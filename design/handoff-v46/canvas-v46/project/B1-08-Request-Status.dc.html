Layout (AR-3)
Reference and status at the top → one next action (only when there is one) → what you asked for vs what was approved → short history. Nothing else.
Three separate facts
Approval, payment and activation are different events with different statuses. “Approved” never reads as “active”; “Payment started” never reads as “paid”.
Payment (PU-12)
External route only. Provider-neutral summary of what will be activated. No amount until pricing exists (ND-08), no payment method collected here, no refund wording, no “mark paid”.
Not designed
Reply to an information request (T-03 / PU-11 OPEN) · Declined (T-02 / R21 — no declined state exists) · how the requester reaches this page later (R01).
Access active
Next action is Sign in — for the institution administrator. How that account is created (T-11) is OPEN.
Who can open this page
It shows private details (institution, contact person, history). How the requester is identified before seeing it is OPEN (T-01 / R01). The reference number identifies the request — it does not open the page on its own. No reference lookup, OTP, magic link or account registration is designed.
