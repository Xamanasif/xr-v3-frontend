Policy safety check

RuleHow Batch 3 meets it
Progress is per formatOnly WEB / AR / VR / MR words. No percentage, no overall completion, no “experiment completed”, no course-level verdict (script check over every Batch-3 board).
Completion contract (T-12)Completed only when the simulation or the headset reports it. No “I have finished” / “Mark as complete” anywhere (script check).
Resources (T-13 / T-15)Opening shows “Opened (date)”; it never counts towards progress. Resources open in a new tab.
Gating (T-16)No locks, no unlocking, no order between formats or stages.
AssessmentNo pass mark, duration, attempts or deadline. Assessment tab and sidebar link open the register (Batch 4).
Formats inherited (LD-1)Formats come from the institution’s access; no format picker; AR “Not included for your institution”, MR “Not available for this experiment”.
Feedback (§P · T-25)Five statements verbatim; one record per format; no edit or resubmit; not shown to Faculty, Institute Admin or Super Admin; no analytics.
Device chain (T-32 / D20a · D20b)Institute Admin forwards only; Super Admin approves only. No Decline / Declined. No device registry, serial lookup or device integration.
Institutional ≠ Student accessUsage counts students with access through grants; ACC-0107 stays the institution’s plan; nothing gives a student access automatically.
Requests to BITS (T-01 / T-07 / T-08)Renewal mirrors the current plan; More licences asks only the number; approval leads to the Batch-1 payment page, where “Nothing changes until the payment is confirmed”. No payment taken here.
No invented infrastructureNo real sign-in, payment processing, XR runtime, simulation imagery, grading automation, notifications (T-34), exports (R15 / T-33) or saved data. Launch WEB shows the state the product would show; nothing runs.
No demo switchingOne person per frame; the live chain uses three separate frames, not a role switcher.
Licence counting (D7)No consume / release / “in use” wording; “More licences” is a request, not a count change.
