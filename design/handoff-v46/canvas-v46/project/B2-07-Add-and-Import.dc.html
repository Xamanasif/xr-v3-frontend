Steps
Choose a file (template + required columns) → Check rows (the platform parses and reports) → Confirm import → Result. The brief’s five moments map onto these three steps plus the result page.
Required columns
student_id, full_name, email, programme, course, course_code — all required (the established student CSV data: programme, course, course code and student details). An empty or invalid value in any of them is an error on that row. The template download has exactly these columns.
Commit mode — interim, not final
The frames show “nothing is imported while the file has errors” (all-or-nothing). This is a temporary design assumption taken from the handoff register (T-24 “errors block”); the inventory lists T-24 as “build choices, not confirmed”. All-or-nothing versus importing only the valid rows stays OPEN (T-24). If it changes, only the Step 2 message and its button change.
Warnings
The inventory lists a warning state for IA-11, but no warning condition is defined. None is drawn: a missing programme, course or course code is an error, not a warning. Which conditions, if any, should only warn is part of T-24.
Duplicates
Duplicate student IDs inside the file, or IDs / e-mails already in People, are errors with the row number.
Not designed
Invitations, account activation, an external provisioning provider, XLSX (D-09-10), ERP precedence (ND-04).

Import states

Step 2 · errors block the import · interim commit modeDuplicate ID, empty programme, short e-mail and empty course code are all errors. A missing required value is never a warning. “Nothing is imported while the file has errors” is the interim all-or-nothing assumption (T-24 open).
