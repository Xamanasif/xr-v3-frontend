When a dialog is allowed

DL-1 · Confirm

An action that is hard to undo or has an effect beyond this page. One sentence on the effect. Examples: Publish, Release, Approve transfer, Remove from group.

DL-2 · Confirm with reason

Return, send back, withdraw, pause, hold and similar actions. The reason is required and is shown to the person affected — the dialog says who will see it.

DL-3 · Small edit

One short value: rename a group, change a course code. Two fields at most. Anything longer is an AR-8 page.

Never a dialog for: forms with sections, anything that scrolls, choosing from long lists, guided steps, reading a record, or a decision that needs the record beside it (that is AR-4).

States · focus, validation, busy

Action order: Cancel first (quiet), the confirming action last and strongest. Destructive confirmations use the red button and put initial focus on Cancel; other confirmations focus the first field, or the primary button when there is none.

Keyboard path and phone layout

  1. Enter or Space on the trigger opens the dialog. The page behind becomes inert.
  2. Focus moves into the dialog: first field (DL-2, DL-3), primary button (DL-1), or Cancel (destructive DL-1).
  3. Tab / Shift+Tab cycle through Close, the field, Cancel and the confirming button — and never leave the dialog.
  4. Esc is Cancel: nothing changes. A typed reason is discarded only after Cancel.
  5. On submit with an error: focus goes to the first invalid field; the message is read with it.
  6. While busy, buttons ignore repeat presses; the label says what is happening.
  7. On close, focus returns to the trigger; a success notice on the page confirms the result.
