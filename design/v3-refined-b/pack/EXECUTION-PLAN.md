## 2. Start now

- Claude Design: Super Admin complete role, Institute Admin complete role and Shared Surfaces can start as separate sessions with their own role pack.
- Claude Code: start the foundation-only migration controller in one isolated worktree. It does not need to wait for all role designs, and it must not invent the missing ones.
- Student, Faculty, Vendor, Reviewer, Content Manager and Public non-landing can also begin when account capacity permits. All are independent workstreams with a common foundation; a sequence number is not an obligation to wait for previous work to finish.

A practical first wave is three design sessions plus one code session, increasing only if usage and progress remain healthy. This is an operational suggestion, not a restriction to partial roles. Parallel sessions share account limits and need not make progress at identical speed.

## 3. End-to-end role delivery

Each designer works through its full ID list internally and exports a complete source package. The owner reviews the actual whole-role navigation and major interactions; there is no additional Codex audit cycle. Real bugs are still fixed.

Approved full-role exports enter the same Claude Code integration queue. While one role is integrated, other design roles continue. Each complete role retains working navigation to all other existing frontend destinations.

## 4. Shared surfaces and dependencies

XS owns sign-in/account/help once. All role designers can start using that agreed behavior and current Refined B primitives; source imports are assembled centrally. No role may deliver a different menu/help theme. A pending shared component is labeled as an assembly dependency, not concealed as a dead link.

Publication (VE -> RV -> CM), corrections (CM -> RV -> SA), access (PU -> SA -> IA -> ST), assessment (FA -> ST -> FA -> ST) and device transfer (ST -> IA -> SA) are cross-role contracts. Their final live data continuity is verified in the existing frontend, not claimed across isolated design canvases.

## 5. Speed with clear stop conditions

Do not design several competing themes, re-render unrelated old screenshots or run the whole regression suite on every edit. Reuse exact components and source references. Do render and test new work before handing it over, and run the stabilized role/final gate in Code.

No fixed completion date is promised by this package. Track actual role completion, exported sources and code migration; use the first complete-role implementation to estimate throughput. Screen generation alone is not implemented prototype completion.

## 6. Landing distinction

The owner's V1 landing remains locked, including its 'For institutions' section. Public non-landing design is separate. The current app's simplified homepage will not be silently counted as restored; a separate fidelity-integration task is held until the owner authorizes it and the missing authorized assets are available.
